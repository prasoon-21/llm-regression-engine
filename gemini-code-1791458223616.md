# LLM CI/CD Regression & Red-Teaming Engine
## Implementation & Deployment Specification

---

## 1. System Container Topology

The runtime environment uses isolated Docker containers to ensure consistent execution across local development, testing, and production.

* **API Gateway (`tiangolo/uvicorn-gunicorn-fastapi:python3.11-slim`)**
  * Ingests GitHub Webhook payloads.
  * Verifies webhook cryptographic signatures.
  * Fetches repository configuration.
  * Pushes evaluation jobs into the task queue.

* **Task Broker & Transient State (`redis:7-alpine`)**
  * Maintains evaluation queues.
  * Tracks intermediate task execution states.
  * Enforces rate limits per repository/organization.

* **Unified Model Proxy (`ghcr.io/berriai/litellm:main-latest`)**
  * Normalizes model provider calls (OpenAI, Anthropic, Gemini, etc.).
  * Manages BYOK (Bring Your Own Key) routing dynamically.
  * Enforces prompt/completion token limits.

* **Evaluation Worker Engine (`python:3.11-slim` + `node:20-alpine`)**
  * Executes LangSmith trace harvesting workflows.
  * Compiles datasets and executes Promptfoo test runs.
  * Runs Instructor/Pydantic validation layers.
  * Evaluates LLM-as-a-Judge semantic rubrics.

* **Persistent Storage (Remote Supabase / `postgres:16-alpine`)**
  * Stores user organizations, repository tokens, historical regression metrics, and test pass/fail logs.

---

## 2. Step-by-Step Implementation Plan

### Phase 1: Infrastructure & Orchestration Setup
* **Container Bridge Networking:**
  * Link the API Gateway, Worker, Redis Broker, and LiteLLM Proxy in an isolated Docker network.
  * Map environment secrets (`GITHUB_APP_PRIVATE_KEY`, `LANGSMITH_API_KEY`, provider API keys).
* **GitHub App Configuration:**
  * Register the GitHub App with repository permissions:
    * `Pull Requests` (Read & Write)
    * `Checks` (Read & Write)
  * Set webhook target URL to the API Gateway ingestion endpoint.

### Phase 2: Data Extraction & Test Case Synthesis
* **LangSmith Ingestion:**
  * Query LangSmith runs using workspace credentials filtered by project and prompt tags.
  * Extract input payloads, intermediate reasoning steps, and expected outputs.
* **Test Suite Compilation:**
  * Convert extracted traces into structured Promptfoo-compatible test suites.
  * Augment test cases with synthetic adversarial inputs (prompt injections, format-breaking payloads).

### Phase 3: Validation Engine Execution
* **Model Inference Routing:**
  * Route test inference requests through the local LiteLLM proxy container using user-provided API credentials.
* **Multi-Layer Assertion Pipeline:**
  * **Schema Conformance:** Validate response structures against schemas using Instructor and Pydantic.
  * **Semantic Quality:** Run LLM-as-a-Judge evaluations for instruction adherence and output completeness.
  * **Safety & Performance Audits:** Track token usage deltas, execution latency spikes, and policy violations with LangKit.

### Phase 4: Feedback Loop & CI/CD Gating
* **Status Aggregation:**
  * Calculate aggregated pass rates, regression deltas against baseline, and token usage metrics.
* **GitHub Checks & PR Integration:**
  * Set the GitHub Commit Status Check to `In Progress` during execution, updating to `Success` or `Failure`.
  * Post a formatted Markdown regression report directly as a PR comment.
* **Telemetry:**
  * Log execution metrics (run duration, failure distribution, token consumption) to PostHog.

## 3. Verification & Testing Milestones

1. **Service Connectivity:** Verify inter-container networking between API, Worker, Redis, and LiteLLM proxy.
2. **Webhook Verification:** Trigger a simulated PR event to confirm job ingestion into Redis.
3. **Trace Ingestion Test:** Confirm successful trace retrieval and extraction from LangSmith.
4. **Headless Execution:** Run Promptfoo test execution inside the worker container and verify JSON output creation.
5. **PR Bot Feedback Test:** Verify automated status check updates and Markdown comment rendering on GitHub PRs.
